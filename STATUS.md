# SnapGit — статус

На 11 сентября 2026 года:

- `SnapGit.py` — рабочая Python-версия программы резервного копирования Git-проектов;
- `README.md` — описание функций, параметров, `.snapignore` и структуры бэкапа;
- используются симметричные команды `backup PROJECT_ROOT` и
  `restore PROJECT_ROOT`;
- Python-версия проверена на тестовом репозитории с Unicode, пробелами, tracked,
  untracked и ignored файлами;
- поддерживается повторение структуры каталогов через `--source-root` или
  `SNAP_SOURCE_ROOT`;
- поддерживается ежедневное уплотнение снимков текущего проекта через
  `--compact-day` или `-cd`, без изменения архивов других проектов;
- поддерживается месячное уплотнение текущего проекта для всех месяцев до выбранной
  границы через `--compact-month` или `-cm`, без изменения архивов других проектов;
- реализован безопасный режим `restore` для восстановления snapshot-time untracked
  и ignored файлов с `--dry-run`, `--overwrite` и `--allow-incomplete`;
- новый снимок завершается файлом `snapshot.json` с версией формата, Git commit,
  branch/remote, состоянием staged/unstaged/deleted, SHA-256, правами и данными
  символических ссылок;
- реализован `restore --mode full`: проверка целостности, checkout сохранённого
  commit, восстановление всех файлов и повторение tracked-удалений;
- старые снимки без `snapshot.json` остаются пригодны для режима `extras`, но не для
  полного восстановления;
- сравнение путей и применение `.snapignore` учитывают Git `core.ignorecase`, поэтому
  Linux-репозитории могут содержать разные пути, отличающиеся только регистром;
- `snapshot.json` корректно экранирует и восстанавливает допустимые в Linux имена,
  содержащие байты вне UTF-8;
- backup, `restore extras`, `restore --mode full`, символические ссылки, Unix-права,
  регистрозависимые пути и не-UTF-8 имена проверены в WSL 2 с Ubuntu 26.04,
  Python 3.14 и Git 2.53;
- проверена обработка отсутствующего `.snapignore` с кодом завершения `1`.

Осознанное ограничение полного режима:

- staged и unstaged пути записываются в манифест, но граница индекса Git не
  воссоздаётся: восстановленные локальные изменения остаются в рабочем дереве.

Дальнейшие улучшения отложены до накопления опыта практического использования.
